\section{Introducción}
La materia de modelado y programación, además de ser una materia formativa, se considera como una materia la cual tiene como objetivo obtener la experiencia para integrar las habilidades de programación y modelado aplicando los conocimientos adquiridos en los primeros semestres de la licenciatura de Ciencias de la Computación.
Bajo este contexto, es que se presenta este primer proyecto de Modelado y Programación, el objetivo de este proyecto es el poder desarrollar desde 0 un sistema de chat funcional donde múltiples clientes solicitan servicios desde un hilo de ejecución, emepleando programación asíncrona .
Para la construcción del servidor se optó por utilizar el elenguaje de programación Rust, esto debido a como es que este lenguaje maneja la memoria, además de que en el contexto actual se está iniciando a re-escribir código muy imoprtante en este lenguaje de programación, como bien podría ser todo el OS de Windows, o las pruebas que se están realizando en el kernel de Linux. En cuanto al cliente, se optó por utilizar el framework de Flutter, el cual es un proyecto Open-Source realizdo por Google, siendo OOP, ideal para construir interfaces gráficas
El alcance del proyecto contempla el diseño estructural de tanto el Server, como del Cliente. El server asume el rol de establecer conexiones duraderas, almacenar el estado de los usuarios y transmitir mensajes de forma concurrente y asíncrona. En contraste, el cliente asume la responsabilidad de traducir los eventos físicos del usuario en comandos empaquetados, aislándolo completamente de la complejidad técnica de la red. Ambos extremos se comunican mediante un protocolo estructurado que garantiza que cualquier cliente de la clase pueda conectarse a cualquier servidor.
Durante la fase de modelado, se establecieron patrones de arquitectura como el Modelo-Vista-Controlador (MVC) y el diseño *Top-Down*. No obstante, el desarrollo no estuvo exento de dificultades; a medida que se implementaron soluciones de concurrencia, surgieron problemas severos de legibilidad que dificultaban la identificación de funciones en el código, requiriendo una refactorización completa de los archivos en ambos componentes.
A lo largo de este reporte se detallará de forma exhaustiva el modelado del sistema, la justificación detrás de cada decisión arquitectónica, la implementación técnica de las herramientas seleccionadas y las conclusiones obtenidas de esta experiencia integral de desarrollo de software.
